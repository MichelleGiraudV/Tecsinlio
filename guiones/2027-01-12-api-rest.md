# Reel 12 · ¿Qué es una API REST? (hecho: r12, voz Marta · Inworld)

Duración objetivo: 35-45 s · Tag: API

## Escena 1 · Hook
- **Título en pantalla:** ¿Qué es una API REST?
- **Visual:** Móvil 📱 ↔ servidor, con peticiones yendo y viniendo.
- **Voz:** "Cada vez que abres una app, por detrás está hablando con una API. ¿Qué es una API REST?"

## Escena 2 · Metáfora
- **Título en pantalla:** API = camarero 🍽️
- **Visual:** Tú → camarero → cocina → respuesta.
- **Voz:** "Una API es como el camarero de un restaurante: tú pides, él va a la cocina y te trae la respuesta."

## Escena 3 · Recursos
- **Título en pantalla:** Todo es un recurso
- **Visual:** `/usuarios` · `/usuarios/42` · `/pedidos`
- **Voz:** "En REST, todo son recursos, y cada uno tiene su dirección. Por ejemplo, barra usuarios."

## Escena 4 · Verbos
- **Título en pantalla:** Los verbos
- **Visual:** GET leer · POST crear · PUT cambiar · DELETE borrar (con `/usuarios/42`).
- **Voz:** "Y usas verbos: GET para leer, POST para crear, PUT para cambiar y DELETE para borrar."

## Escena 5 · Respuesta
- **Título en pantalla:** JSON + código
- **Visual:** `GET /usuarios/42` → 200 OK + `{ "id": 42, "nombre": "Ana" }`; `GET /usuarios/999` → 404 Not Found.
- **Voz:** "La respuesta llega en JSON, con un código: doscientos si todo va bien, cuatrocientos cuatro si no existe."

## Escena 6 · Cierre
- **Título en pantalla:** Recurso. Verbo. Respuesta.
- **Voz:** "Recurso, verbo y respuesta. Guárdalo y sígueme para más tec sin lío."

---
Notas técnicas: REST usa URLs para identificar recursos y métodos HTTP para la acción (GET lee, POST crea, PUT reemplaza/actualiza, PATCH actualiza en parte, DELETE borra). Las respuestas suelen ser JSON con códigos de estado HTTP (200 OK, 201 Created, 404 Not Found, 500 error del servidor).

Caption sugerido:
¿Qué es una API REST? 🍽️

API = el camarero entre tu app y el servidor.
📍 Recurso → /usuarios
🔧 Verbo → GET, POST, PUT, DELETE
📦 Respuesta → JSON + código (200 ✅ · 404 ❌)

💾 Guárdalo
💬 ¿Qué API usas más?
